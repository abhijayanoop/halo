# Decisions
One line each: date — decision — why — rejected alternative.

- 2026-10-10 — pywebview + React for the HUD — one Python process, packages with PyInstaller — Electron (second runtime, larger build)
- 2026-10-10 — GitHub repo created under github.com/abhijayanoop, public — that's the account the user wants this work attributed to — the already-active `abhijayanoop-elcarreira` CLI session account
- 2026-10-10 — `Skill` protocol modeled as a `run(self, ctx, args)` method, not `__call__` — matches the spec's literal wording and still structurally satisfies a bare module-level `async def run(ctx, args)` — a `__call__`-based Protocol
- 2026-10-10 — `MemoryItem.privacy` is an explicit field, copied from the destination note's frontmatter at write time — lets the cloud-prompt raising check in `models/client.py` enforce the privacy rule on `MemoryItem`s alone, without reaching into the vault — inferring privacy only from the note at read time
- 2026-10-10 — pywebview confirmed as the HUD host (frameless, always-on-top, JS-driven resize all verified on Windows), no fallback needed — n/a — square frameless window / Electron
- 2026-10-10 — claude-agent-sdk confirmed for the Day 4 coding worker (streaming and `can_use_tool` both verified against a scratch repo; reuses the existing `claude` CLI login) — n/a — plain `claude -p --output-format stream-json` CLI invocation
- 2026-10-10 — Voice (ASR) ships as a secondary input for v0.1; typing/push-to-talk stays primary — Parakeet CTC 110M int8 decodes in <200ms but is inaccurate on live mic audio; the matching transducer variant fails to load (sherpa-onnx version incompatibility), and Wispr Flow's MCP server doesn't do speech-to-text at all (and would break the local-only voice constraint anyway) — switching ASR model/vendor now to chase accuracy
- 2026-10-10 — CI's secret scan installs the gitleaks CLI binary directly rather than using `gitleaks/gitleaks-action` — that action is commercially licensed for orgs and is being deprecated (Node 20 runner removal) — `gitleaks/gitleaks-action`
- 2026-10-10 — `docs/` excluded from ruff's lint/format scope — it's reference/planning markdown with illustrative code snippets, not shipped code — reformatting the playbook/architecture docs' embedded snippets to satisfy ruff
- 2026-10-11 — Run-level events (`run.started`, `approval.requested/resolved`, `run.finished/failed`) are emitted by `HaloRunner`, not by graph nodes — LangGraph re-runs an interrupted node from its top on resume, so node-emitted events would duplicate — emitting from nodes and de-duplicating by event id
- 2026-10-11 — Graph dependencies (model client, skill registry, emit) are passed by closure in `build_graph(deps, checkpointer)` — simplest, and nothing non-serializable touches the checkpoint — LangGraph `context_schema`/`Runtime`
- 2026-10-11 — Graph state allowlists Halo's models in the checkpoint serializer (`allowed_msgpack_modules`) — state stays typed and the "will be blocked in a future version" warning is gone — storing plain dicts in state, or `pickle_fallback`
- 2026-10-11 — The local API refuses any request whose Host or Origin is not localhost (HTTP and WebSocket) — `/approve` and `/run` must not be callable from a web page in the user's browser (CSRF, DNS rebinding) — no guard, or a shared secret token only
- 2026-10-11 — Router fills args that merely echo the user's words (`message`, `text`) in code when the model omits them — one fewer thing the model can get wrong — failing the step on a missing arg
- 2026-10-11 — Model access key is read from `NEBIUS_API_KEY` (via .env), model ids and prices live in config, ids starting `UNSET` make the client refuse to call — nothing can run live by accident — hard-coding catalogue ids before they are known
- 2026-10-12 — Until the Token Factory key arrives, dev runs use Nemotron served by NVIDIA's hosted API (build.nvidia.com, OpenAI-compatible) through a config "profile"; Token Factory stays the target for the submission and for every published number — keeps the same model family so prompts and JSON/tool-call behaviour carry over, and unblocks the live checks now — Qwen/Kimi or a small local model (different behaviour, so prompt tuning would not transfer), waiting idle for the key
- 2026-10-12 — `.claude/rules` path globs now use `src/halo/**` — the code lives under `src/`, so the old `halo/**` globs never matched — leaving the rules unloaded
- 2026-10-12 — `nvidia-api` profile uses `nvidia/nemotron-3.5-lightning-30b-a3b` as the Nano stand-in (Super/Ultra/Omni use their Nemotron 3 ids) — the catalogued `nemotron-nano-3-30b-a3b` returns 404 for our account; Lightning is the same 30B-A3B class, so prompts should transfer, but numbers do not (only Token Factory runs are published) — waiting for access, or the older Llama-Nemotron models (also 404)
- 2026-10-12 — `build_client` no longer calls `load_dotenv`; entry points (`halo`, the API server) call `load_env()` first and live tests load `.env` via a fixture — the implicit load found the real `.env` from two offline tests and leaked `HALO_PROFILE` and the key into every later test — keeping the implicit load and adding per-test isolation only
- 2026-10-12 — Tool-calling and JSON-schema output are reliable enough on all three tiers (60/60 valid, `json_schema` mode, no `instructor`), so Nano does tool calls — measured on the NVIDIA API dev profile with a small sample; re-check on Token Factory — routing tool calls through Super only
- 2026-10-12 — Deviation from PLAN Day 1 item 6: no `finalize` node; `HaloRunner` builds the final result and emits `run.finished` — run-level events must not come from nodes (an interrupted node re-runs on resume) and the final status is computed from the step results anyway — a `finalize` node that emits events
- 2026-10-12 — A plan step's risk is `max(model's label, the skill's manifest risk, the skill's assess_risk(args))`; the model can raise a step's risk, never lower it — plans can be steered by untrusted context, so the approval gate must not trust the model's own label — trusting `Step.risk` as returned
- 2026-10-12 — The local API accepts an Origin only if it is the server's own origin or the UI dev server (localhost:5173), not any localhost port — a page served by any other local server (notebook, `http.server`) could otherwise drive /run and /approve — "any localhost origin"
- 2026-10-12 — `privacy: local` matching uses 4-word shingles of each local note over a normalized prompt (case, punctuation, whitespace ignored) — whole-note substring matching let a copied line or excerpt through — whole-note match only
- 2026-10-12 — `run.failed` carries a fixed reason per error type, never the exception text — events are written to the JSONL flight recorder and streamed on /events, and provider errors can echo request content — `str(exc)` in the payload

- 2026-10-12 — Approvals carry an `approval_id` (ULID made by the gate node, stored in the checkpoint); `ApprovalDecision` and `POST /approve` must echo it, mismatch is a 409 and the run keeps waiting — a stale, repeated or wrong-step click must not approve the next step; applied via /add-event, so `ApprovalRequest`/`ApprovalDecision` and their schemas changed — an id derived from run_id + step index (guessable, and reused if a step is retried)
- 2026-10-12 — The Day 3 permission-card demo uses Notepad, not Spotify — Spotify is not installed on the dev laptop and a Start-menu app cannot be launched without a shell; Notepad is on PATH on every Windows install and is not on the allowlist — installing Spotify just for the demo
- 2026-10-12 — The `/events` handler no longer awaits its cancelled helper tasks in cleanup (done-callback retrieves them) — parked in `gather` while being cancelled (client reconnect, shutdown), anyio re-delivered the cancel, the task's cancel count hit 2 and a CancelledError leaked; reproduced 1 failure in ~28 rounds, 0 in 200 after — keeping `gather(return_exceptions=True)` in the `finally`
- 2026-10-12 — A skill can mark a step not grantable (`grantable(args)`); `app.open` is grantable only for allowlisted apps, and `ctx.approved` is never set for a low-risk step — review showed one "Always for this task" click on one unlisted app would have let a later, different unlisted app launch unseen — keying grants by (tool, args), which would have broken the existing tool-level grant tests
- 2026-10-12 — Programs are looked up on PATH only, one entry at a time, never the current folder — on Windows `shutil.which` tries the current folder first, so a planted `code.cmd` could run with no approval — trusting `shutil.which`
- 2026-10-12 — The approval card shows the skill's own description of the step (`describe(args)`: only the validated app name), not the raw args — extra keys from a poisoned plan could make the card read like a different app — rejecting extra args, which would have changed an existing test's assertion
- 2026-10-12 — `open_path` (page-callable) checks the text before touching the filesystem (no `\\` or `//` paths, same drive as an allowed root) and opens documents only, never programs — resolving a network path itself connects to it and leaks the login hash — a bare `resolve()` then a root check
- 2026-10-12 — Mood events carry the status line (`payload.line`): a template at once, a refined Nano line later only if still current; the UI takes the status line only from mood events once one has arrived — keeps the line in step with the face and needs no contract change (payload is free-form) — a new event type
- 2026-10-12 — Nano status lines are opt-in (`HALO_STATUS_LINES=1`) — each is a model call and Nano takes 2-8 s on the dev profile, so every line would time out; templates always work — on by default
- 2026-10-12 — Timed moods (Delighted, Remembering, Confused, Guarding) count their hold from when the face is shown, not from the event, and Confused/Guarding fade after 6 s — the 700 ms dwell had shortened Delighted to 1.3 s, and a Confused face blocked sleep forever — counting from the event
- 2026-10-12 — `/events` sends a late or reconnecting HUD the current mood and every open approval card — a dropped socket would otherwise leave a run paused with no card — replaying the whole bus history
- 2026-10-12 — The HUD is served by the local server (same origin) and gets the token in the URL hash — no CORS, no `file://` null Origin, and the hash is never sent in requests, logs or Referer — `file://`, or the token in a query string

- 2026-10-17 — Mascot shapes are clean SVG paths animated with Framer Motion springs; Rough.js and the 8 fps redraw are gone; the one test that asserted the redraw was replaced (approved by the user) — the sketchy wobble read as unfinished on the glass bar, and each mood now has its own eyes + mouth + brow so the face reads without the accessory — keeping Rough.js for the outline
- 2026-10-17 — The HUD keeps its three fixed window sizes (bar 260x44, card 380x140, panel 420x600) and gets its life from the glass tinted by mood or risk, cursor-following eyes, a fading status line and a progress bar; the planned "hidden when idle" bar is dropped — the existing tests lock those sizes and the 200 px minimum window clamp would leave an invisible click-blocking strip; the window is now transparent so the pill has real rounded corners — a hidden/peek/active window that resizes on hover
- 2026-10-17 — The HUD window is opaque (#0b0c0f) and cut to a rounded shape with a window region that is re-cut on every resize (radius = half the height for the bar, 16 for the card and panel), with the minimum window size set to the bar's own; the earlier transparent window (colour-keyed form) is reverted — a colour-keyed form makes every pixel the window itself draws click-through, and the web page is drawn by a separate layer, so clicks fell through to the app behind and a faint box showed at the edges; verified in the real window with a real mouse click — a transparent window with WebView2
- 2026-10-17 — "Always for this task" grants are held in memory per run (GraphDeps.grants), never in the SQLite checkpoint — CONTRACTS.md says they are session-scoped and never persisted; after a restart Halo asks again — keeping them in the checkpoint, which retry() would then reuse
- 2026-10-17 — retry() emits a second run.started (payload.retry) — the HUD and mood engine drop the old failure instead of showing it while the retry works; the one existing assertion that counted run.started was updated with the user's approval — having the UI infer a retry from events that follow run.failed
- 2026-10-17 — Stop reuses run.finished with status "denied" and stopped=true (a working run is cancelled, a run on a card is denied) — the status lines already word it "Stopped, as you asked" and no mood treats it as success or failure, so no contract change was needed; Pause is not built because a model call in flight has no clean pause point — a new run.cancelled event type, which would have changed the frozen contract
- 2026-10-17 — Each event-bus subscriber queue is bounded (1000) and drops its oldest event when full — a client that stops reading must not grow memory; a stuck HUD gets the catch-up on reconnect — blocking the publisher or disconnecting the client
- 2026-10-17 — Paused runs found in the checkpoint at startup are offered to the next HUD (HaloRunner.paused_approvals, newest 50 runs) — otherwise a card open when Halo quit never came back — only tracking approvals seen since the process started
- 2026-10-17 — Memory ships keyword search (SQLite FTS5, stemmed) with RRF written to take more ranked lists; vector search is not built — there is no embedding model in the config and every model call must go through the Nemotron client, so adding one needs a decision on which embedding model to use; fact similarity for duplicates uses word overlap (>= 0.8) instead of cosine — sqlite-vec with an unconfigured embedder
- 2026-10-17 — A memory is one bullet with inline fields and a block id (a bullet without an id gets a stable hash id); writes touch only their own line and keep line endings; facts are stripped of brackets and carets so text from anywhere cannot forge fields or ids — rewriting whole notes through a YAML/Markdown library
- 2026-10-17 — Notes created under Finance/ are privacy: local, and the guard's local_texts are the full text of every privacy: local note; a request that copies one is refused before any model call — only the bullets, which would miss prose
- 2026-10-17 — memory.recall never calls a model, so it may show a privacy: local fact on the user's own screen; the cloud context (assemble_context) never includes one — asking "what is my salary" should work, but no prompt may carry it
- 2026-10-17 — memory.forget needs the permission card (medium risk, never an always-grant) and deletes at most three lines, each containing every meaningful word of the query — a vague "forget tea" must delete nothing rather than the wrong thing
- 2026-10-17 — Proposed memories are extracted only from the user's own words, marked agent-proposed with medium trust whatever the model says, listed in Inbox/proposed-memories.md (never indexed) and written to a real note only on Approve; extraction costs a Nano call per finished run so it is opt-in (HALO_MEMORY_EXTRACT=1); Edit-before-approve and contradiction/supersede marking are not built — letting a page, file or tool output plant a memory
- 2026-10-17 — The vault is ~/HaloVault, or inside an explicit home (tests), or the config's vault.path — tests and sandboxes must never touch the real vault
- 2026-10-17 — The nvidia-api dev profile sends chat_template_kwargs.enable_thinking=false: a Nano router call went from about 4 s to under 1 s and the router scored 20/20 (live, dev profile, 3 probes per setting plus the 20-case set; reasoning_effort=low did not help); it applies to every tier, so planning quality on Super/Ultra is unmeasured — a per-tier setting, which needs per-call extra_body in the client
- 2026-10-27 — The token-factory profile uses base_url https://api.tokenfactory.nebius.com/v1/ with Nano nvidia/NVIDIA-Nemotron-3-Nano-30B-A3B, Super nvidia/nemotron-3-super-120b-a12b and Ultra nvidia/Nemotron-3-Ultra-550b-a55b (ids read from the models endpoint); Omni stays unset because no Nano Omni is listed — guessing a different multimodal model for a tier nothing uses yet
- 2026-10-27 — Thinking stays on for Token Factory (router 20/20 at 1.7 s mean) while the nvidia-api dev profile keeps it off — off scored 18/20 on Token Factory at 0.8 s; accuracy won, and only Token Factory runs are published — copying the dev setting to both profiles
- 2026-10-27 — Vector search is skipped for now: the only embedding model on Token Factory is Qwen/Qwen3-Embedding-8B, which is not Nemotron, and the project rule is Nemotron only — an exception to the rule, or a local fastembed model (revisit after Day 4 and security)
- 2026-10-27 — ~/.halo/config.toml overrides the packaged defaults section by section instead of replacing them, and Halo uses the vault at C:/Users/abhij/Documents/main-folder/HaloVault set there — a file with only [vault] would otherwise drop the apps and model profiles
- 2026-10-27 — The brief writer and reviewer live in `halo/coding/`, not `skills/code_task/` — the registry loads every folder under skills/ and rejects one without a manifest and `skill.py`, so a half-built skill would break startup; the skill (task 6) imports from `coding/` — putting them in skills/code_task/ now
- 2026-10-27 — A TaskBrief's `test_cmd` is always set from the project note, never taken from the model, and `likely_files` keeps only paths that exist in the repo's file list — Halo runs the test command itself, so a model-chosen (or injected) command would be arbitrary execution — trusting the model's `test_cmd`
- 2026-10-27 — The reviewer gets the diff only as a fenced data block through `reader.as_data_block`, with no tools, returns a bounded `Review` that stays `Tainted`, and a failed test run caps the verdict at `concerns` — the diff is Claude Code's output (untrusted) and Halo's own test run outranks a model opinion; a verdict never merges, the user approves that — letting the model's `pass` stand over failing tests
- 2026-10-27 — A permission card from inside the coding worker is answered through the same `POST /approve` route: the server checks a `WorkerApprovals` registry (run id + approval id) first and falls back to the graph; a stale id while a worker card waits is a 409 and the card keeps waiting; worker cards never take an "always" grant, and no answer in `approval_timeout_s` is a denial — a second endpoint would have needed HUD changes, and an "always" grant on a model-driven shell is the thing the approval rules forbid — a separate worker-only endpoint
- 2026-10-27 — The worker has two gates: a PreToolUse hook that denies paths outside the worktree, anything inside `.git`, and the network, and `can_use_tool`, which turns anything not pre-approved into a high-risk card; pre-approved tools are file tools plus exactly `Bash(<test_cmd> *)`, `git diff` and `git status`, with no shell metacharacters — the spike showed Claude Code answers some reads itself without calling `can_use_tool`, so the callback alone is not a gate — relying on `can_use_tool` alone
- 2026-10-27 — Coding runs are capped at ₹150 (a first live run showed one Claude Code turn costs about ₹13, so ₹40 allowed about three turns), 30 turns and 900 s by default (`[coding]` in config.toml); the SDK's dollar cap is the rupee cap divided by `usd_to_inr`, and hitting a cap returns a status (`max_turns`, `budget`, `timeout`) with the partial cost, never a crash; the user's own Claude settings are ignored (`setting_sources=[]`) — a user-level setting could loosen the permissions Halo set — inheriting the user's Claude Code settings
- 2026-10-27 — The coding session's two cards (brief, result) are `approval.requested` events with `payload.kind` `code.brief` / `code.result`, answered through `POST /code/decision` {run_id, approval_id, action, brief?, feedback?}; each card offers only some actions (approve/deny; merge/iterate/discard) and anything else is a 422 that leaves the card waiting; a stale id is a 409; no action is remembered for a later card — a result card needs Merge, Iterate and Discard, which the three-valued `ApprovalGrant` cannot say, and a new event type would change the frozen contract — widening `ApprovalDecision`
- 2026-10-27 — `code.task` is one skill that runs the whole session itself (risk low); the brief card is its approval and nothing is created or run before it is answered; the project is chosen by a note name found in the vault's Projects folder, so its path, test command and branch never come from the model or the card; Explain and Plan answer from the repo map with no worker or worktree — the generic gate card would have shown a bare "Can I run code.task?" before the brief card, and a model-supplied path would let a poisoned request point the worker anywhere — a planned multi-step `code.task` and a `path` argument
- 2026-10-27 — Halo runs the project's tests itself with no shell, a timeout and the process tree killed on timeout or Stop; pass or fail is the exit code only; the output is shown cleaned and tainted; names containing KEY, TOKEN, SECRET, PASSWORD or CREDENTIAL are removed from the tests' environment — the tests run user code and Halo's own process holds model keys — passing the full environment
- 2026-10-27 — Stop, an error or a crash during a session discards the worktree and its branch; an unanswered result card (30 minutes) keeps them and the result says where; a refused or conflicting merge puts the result card back with the reason (Halo never stashes or force-merges); iterate is limited to 3 rounds — an abandoned session must not litter the user's repo, but work the user may still want is never deleted on a timeout — always discarding on timeout
- 2026-10-27 — `code.task` is no longer a planned multi-step skill: the planner gives it one direct step (no Super call) and the skill runs its own session; the existing planner, graph and approval tests that used `code.task` as their example multi-step skill now use `trip.plan` (approved by the user) — Super would otherwise rewrite a coding request into steps of other skills, and the model could invent the args — keeping `code.task` in MULTI_STEP_SKILLS
